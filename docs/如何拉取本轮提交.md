## 本轮挖出的最严重 bug：柜型图错位

`detectDuplicates()`原来用「宽±1mm + 高±1mm + 套数相等」判重。
真实 DWG 里本来就有**三对物理不同、但宽高套数完全相同**的柜体：

```
CP-7p-11   1415×2350  7 套   ←→   CP-7p-16   1415×2350  7 套
CP-10p-08  1765×2350  10 套  ←→   CP-10p-22  1765×2350  10 套
CP-13p-01  2115×2350  13 套  ←→   CP-13p-23  2115×2350  13 套
```

它们的图内容互不相同（sha1 各异），而且用户给的权威口径
「**7 units = 3 套**」正说明这些同尺寸柜必须各自保留。

叠加「替换」分支后的连锁反应：

1. `CP-7p-11` 被判成「已存在 CP-7p-16」→ 弹重复提示；
2. 选「替换」→ 后端把 CP-7p-16 的图写进 CP-7p-16 那条记录；
3. 结果 **CP-7p-11 的 `image_path` 指向了 `CP-7p-16.jpg`**，
   在柜型库里点开这个柜，看到的是**另一个柜的图**。

修复：柜型的身份就是 `variant_code`（由 DWG 柜体序号生成，同图重传时不变），
几何相同只能当提示、不能当判重依据。改完后实测：

- 三对柜体各自入库，互不干扰；
- 每条记录的 `image_path` 都等于自己的 `code`；
- 23 张图 sha1 互不相同；
- 同一个 code 重传仍然正确判重（没矫枉过正）。
